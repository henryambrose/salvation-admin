1. Introduction

This Handover Document formally transfers operational responsibility for the Salvation Admin application suite to the designated administrators and data managers of Our Lady of Salvation Church, Dadar.

The document covers all three applications delivered under the project: Members, Fund Management, and Graveyard Management. It serves as the primary reference for day-to-day operation, user management, and ongoing administration.

The Salvation Admin system is a secure, web-based application accessible through a standard web browser. No software installation is required on user computers beyond a modern browser (Google Chrome or Mozilla Firefox recommended).

2. Project Overview

Members Application

The Members application manages the complete Church Members Database. It provides the ability to add, update, and maintain records for all parishioners and their families. It serves as the master data source for the Fund and Graveyard applications, ensuring consistent member information across all three systems.

Fund Management Application

The Fund Management application replaces the previous system that had reached end-of-life. It manages Community Contributions, Annual Family Contributions, and Mass Intentions. The system is directly linked to the Members database to validate payer identities and generate accurate receipts.

Graveyard Management Application

The Graveyard Management application replaces the previous system that had reached end-of-life. It manages the full lifecycle of the church cemetery and niches — from grave booking and payment collection to niche transfers and annual maintenance fees. It integrates with the Members database to validate burial eligibilities.

Key Benefits

  • Centralized, single-source-of-truth for all parish member data
  • Secure access via role-based login — each staff member sees only what they need
  • Complete audit trail — every change is logged with the user and timestamp
  • Digital receipt generation for fund contributions and graveyard payments
  • Export to Excel/CSV for reporting and reconciliation
  • Family tree visualization for member relationships
  • Elimination of duplicate data entry across departments
  • Soft-delete (archive) system — records are never permanently lost unless explicitly confirmed

Logging In

  1. Open the application URL in Google Chrome or Mozilla Firefox.
  2. Enter your assigned Email Address and Password on the login screen.
  3. Click Log In. You will be redirected to the dashboard for your role.
First Login: Each new user should change their password immediately after first login via Settings → Password in the top-right menu.

Forgot Password

Click "Forgot your password?" on the login page. Enter your email address. A reset link will be sent to your inbox. Follow the link to set a new password. Contact the Administrator if you do not receive the email within 5 minutes.

Session Timeout

The system includes a session-refresh mechanism that prevents automatic logout while you are actively filling in a form. However, extended idle periods (leaving the browser tab open without activity) may require you to log in again.

Logging Out

Always log out after finishing your work, especially on shared computers. Click your name/avatar in the top-right corner and select Log Out.

4. User Roles & Permissions

Access is controlled by Roles. Each role grants specific permissions across the three modules. A user may have one or more roles.

Role Typical User Access Level
Super Admin System Developer / IT Administrator Unrestricted access to all modules, audit logs, system configuration, and user management.
Administrator Parish Administrator Full access to Members, Fund, and Graveyard modules. Can manage users and roles.
Data Manager Office Data Entry Staff Add, edit, and view records across assigned modules. Cannot manage user accounts.
Viewer / Read-Only Clergy / Pastoral Staff View and search records. Cannot add or modify data.
Roles and permissions are fully configurable. The Administrator can adjust what each role is allowed to do via Roles & Permissions in the navigation menu.

Managing User Accounts

Only users with the Administrator role (or above) can manage accounts.

  • Create a new user: Go to Members → Users → Add User. Enter the name, email, and assign a role. The user will receive login credentials.
  • Deactivate a user: Find the user in the Users list and use the deactivate/delete action. Deactivated users cannot log in.
  • Change a user's role: Edit the user record and reassign the role.

5. Members Module

The Members module is the foundation of the system. All data here is shared across the Fund and Graveyard modules. Changes to member records are reflected immediately in the other modules.

5.1 Member Records

Each member record holds personal details, contact information, family grouping, and sacramental history. Members are grouped by Family Number; all people sharing the same family number are treated as one household.

Adding a New Member

  1. Navigate to Members → Members and click Add Member.
  2. Fill in the required fields: Full Name, Date of Birth, Gender, Status, and Community.
  3. Assign a Family Number (enter an existing one to link to a family, or a new one to start a new family).
  4. Enter contact details, address, and any other known information.
  5. Click Save. The member is now active in the system.

Editing a Member

  1. Search for the member using the search bar on the Members list page.
  2. Click the member's name or the edit icon to open the record.
  3. Make changes and click Update.

Archiving (Soft Delete) a Member

Archiving hides a member from active lists without permanently deleting the record. Use this for members who have moved away or passed away (use the Death Records for deceased members). Archived members can be restored at any time.

Data Verification

The Data Verification screen provides a bulk-review interface to confirm or correct member details imported from the old system. Staff can approve records one by one or in batches.

6. Fund Management Module

The Fund module manages all financial contributions to the parish — family annual contributions, community group contributions, and mass intention bookings.

6.1 Annual Contributions

Tracks each family's annual contribution to the parish. One record is created per family per year.

Recording a New Annual Contribution

  1. Go to Fund → Annual Contributions and click Add.
  2. Search for and select the family (by Family Number or member name).
  3. Select the Fund Category, Year, and Payment Method.
  4. Enter the amount received and any remarks.
  5. Click Save. A receipt can be downloaded immediately after saving.

Bulk Update

Multiple contribution records can be updated simultaneously (e.g., marking a batch as paid after receiving a group payment). Use the bulk-update option on the Annual Contributions list.

Statuses

StatusMeaning
PendingContribution recorded but not yet paid
PartialPart-payment received
PaidFull amount received

6.2 Community Contributions

Records contributions collected at the community (SCC) level, typically from a group rather than an individual family.

  1. Go to Fund → Community Contributions and click Add.
  2. Select the Community, Contribution Type, and the relevant period.
  3. Enter the total amount collected and the payment method.
  4. Click Save. Update the status as payments progress.

A statistics summary is available on the Community Contributions page to track totals by community.

6.3 Mass Intentions

Records mass booking requests from parishioners — specifying the intention, mass type, and date requested.

Recording a Mass Intention

  1. Go to Fund → Mass Intentions and click Add.
  2. Search for and select the member requesting the mass (or enter manually for external requesters).
  3. Select the Mass Type, Mass Intention Type, and preferred date.
  4. Enter the offering amount and payment method.
  5. Click Save. A receipt is available for download.

7. Graveyard Management Module

The Graveyard module manages the church cemetery and niches. It tracks grave availability, bookings, payments, and the niche transfer (remains transfer) workflow.

7.1 Grave Types

TypeDescriptionMenu Path
Temporary Graves Short-term burial plots. Remains may later be transferred to a permanent grave or niche. Graveyard → Temporary Graves
Permanent Graves Long-term burial plots allocated to a family or individual. Graveyard → Permanent Graves
Niches Wall-mounted compartments for cremated remains (ashes). Graveyard → Niches

7.2 Valid Members

Each grave or niche can have a list of Valid Members — parishioners who are authorized to use that grave/niche. This ensures only eligible members can be booked into a specific plot.

  • Manage valid members via Graveyard → Valid Members.
  • Generate a PDF list of valid members for any grave or niche.
  • Member search is linked to the Members database for real-time validation.

7.3 Booking a Grave

Temporary Grave Booking

  1. Go to Graveyard → Temporary Grave Bookings → Add.
  2. Search and select the available temporary grave.
  3. Search and select the deceased person (member or external).
  4. Enter burial details: burial date, contact number, and any remarks.
  5. Click Save. The grave status changes to Unavailable.
  6. Confirm the booking once payment is received (status moves to Confirmed).
Only Pending bookings can be deleted. Once confirmed or cancelled, a booking cannot be deleted — only cancelled through the proper cancellation process.

Permanent Grave Booking

  1. Go to Graveyard → Permanent Grave Bookings → Add.
  2. Select the available permanent grave and the deceased/assignee member.
  3. Enter booking details and service type.
  4. Click Save. Process payment through the Payments section.

7.4 Niche Bookings

Niche bookings follow the same process as permanent grave bookings. Valid members for each niche must be configured before booking. Navigate to Graveyard → Niches to manage niche records and their bookings.

7.5 Remains Transfer (Niche Transfer)

When remains from a temporary grave are to be moved to a permanent grave or niche, a formal Remains Transfer workflow must be followed.

  1. Create Transfer Request: Go to Graveyard → Remains Transfer → Add. Select the source temporary grave booking and the destination grave/niche.
  2. Approval: An authorized user reviews and Approves or Rejects the request.
  3. Complete Transfer: Once the physical transfer is done, mark the transfer as Completed. This updates the statuses of both the source and destination graves automatically.
  4. Cancel (if needed): A transfer can be cancelled before completion if circumstances change.
Transfer statistics (number of completed, pending, and rejected transfers) are visible on the Remains Transfer summary page.

7.6 Payments

All graveyard payments (booking fees, service charges, maintenance fees) are managed in Graveyard → Payments.

9. Data Management & Backups

Archive vs. Permanent Delete

The system uses a "soft delete" (archive) pattern for most records. Archiving a record hides it from the active list but preserves it in the database. Archived records can be restored.

Permanent deletion removes the record from the database entirely and cannot be undone. It is only available in limited scenarios (e.g., pending bookings). The system will prompt for confirmation before any permanent deletion.

Important: Never permanently delete records unless you are certain they are incorrect entries. Archiving is always the preferred first step.

10. Key Operational Workflows

Workflow A: Registering a New Parishioner Family

  1. Go to Members → Members → Add Member.
  2. Enter the head of household's details. Assign a new unique Family Number.
  3. Save the head of household record.
  4. Add each additional family member using the same Family Number to link them.
  5. Set the appropriate relationship for each member (Spouse, Son, Daughter, etc.).

Workflow B: Processing an Annual Fund Contribution

  1. Go to Fund → Annual Contributions → Add.
  2. Search for the family by Family Number or member name.
  3. Select the Fund Category, Year, and payment details.
  4. Save the record. Status is set to Pending or Paid depending on amount entered.
  5. Download and issue the receipt to the parishioner.

Workflow C: Temporary Grave Burial → Niche Transfer

  1. Book Temporary Grave: Graveyard → Temporary Grave Bookings → Add. Fill burial details. Confirm booking after payment.
  2. Process Payment: Graveyard → Payments → Add Booking Payment. Download receipt.
  3. Initiate Transfer: When family requests transfer to niche, go to Graveyard → Remains Transfer → Add.
  4. Select Source & Destination: Choose the temporary grave booking and the destination niche.
  5. Approve Request: Authorized user approves the transfer request.
  6. Complete Transfer: After physical transfer, mark as Completed. The temporary grave becomes available again and the niche is marked occupied.

Workflow D: Handling a Mass Intention Request

  1. Go to Fund → Mass Intentions → Add.
  2. Search for the requesting member, or enter name manually if external.
  3. Select Mass Type, Intention Type, and preferred date.
  4. Enter the offering amount and payment method.
  5. Save. Download and provide the receipt. Update status to Scheduled once a date is confirmed.

Workflow E: Reporting an Issue or Bug

  1. Note the exact action you were performing and the error message displayed.
  2. Take a screenshot if possible.
  3. Contact the developer/support contact (see Section 12).
  4. Provide your name, date/time of the issue, and the steps to reproduce it.

11. Known Limitations

LimitationNotes / Workaround
Certificate generation is currently disabled The certificate module is built but disabled pending final template approval. It will be enabled in a future update.
Confirmed or cancelled bookings cannot be deleted Only pending bookings can be permanently deleted. For confirmed bookings that need reversal, use the Cancel action.
Payments with records cannot have their booking deleted To remove a permanent grave booking, all associated payment records must first be removed. Contact the Administrator.
Audit logs are viewable by Super Admins only Administrators can request an audit log extract from the Super Admin/Developer if needed.
Internet connection required This is a web-based application. An active internet connection is required at all times.
Browser compatibility Fully tested on Google Chrome and Mozilla Firefox. Internet Explorer is not supported.
